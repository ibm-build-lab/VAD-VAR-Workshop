# AutoAI RAG in watsonx.ai Tutorial: Part One

## Introducing AutoAI RAG
Retrieval Augmented Generation (RAG) has been the most popular and powerful use case for generative AI for enterprise businesses. Once a client has found the right model and setup, RAG can be a powerful tool for many client business use cases. It can provide answers and accurate responses based on validated enterprise knowledge and data.

However, getting to that point can be time-consuming and difficult. It is difficult to compare the outputs of different models in response to different embedding methods and configurations. The client may need to re-run multiple tests to find the best combinations, which is very time-
consuming. When the grounding documents are changed or updated the clients may must pay the same price again. 

IBM watsonx.ai AutoAI RAG provides an easy-to-use and efficient way for clients to test out different combinations to find the best RAG pattern to use for their use case. 

Using AutoAI RAG, clients can try different patterns using different combinations of 
- Models
- Embedding methods
- Chunking size and Chunking overlap
- Metrics
- More …

### 6. **Configure Experiment Settings**  
   - The current setting is provided (**A**), where you will run a test using the **Answer faithfulness** metric, 3 foundation models, and 2 embeddings (subject to changes).  
   ![default config](../images/211/config.png)

   - Click **Experiment settings** (**B**) to review the following:

     #### 1. **Retrieval & Generation Settings**(Contains the following)
     ##### a. **Optimized Metric**: 
     Choose the evaluation metric:
       - **Answer Faithfulness**: Measures token precision—how much of the generated answer matches the retrieved context.
       - **Answer Correctness**: Compares the output against the model answer for token inclusion.
       - **Context Correctness**: Considers the ranking of answers returned by the LLM. 
     - **Selection for Experiment**: Use **Answer Correctness** for the current test.
     
     ##### b. **Retrieval Methods**: 
     Choose between:
       - **Window**: Retrieves relevant information with surrounding context (better for smaller collections).
       - **Simple**: Retrieves only relevant information without context (better for larger collections).
     - **Selection for Experiment**: Choose both **Window** and **Simple** retrieval.

     ##### c. **Foundation Models**: 
     You can select up to three models for comparison. Use the following :
       - granite-13b-instruct-v2
       - flan-ul2-20b
       - mixtral-8x7b-instruct-v01
     
     ##### d. **Max RAG Patterns**: 
     This controls how many combinations of chunking, embeddings, and retrieval methods to test. The default maximum is **8** for this experiment.
     ![settings](../images/211/settings-1.png)

     #### 2. **Indexing Settings**
     ##### a. **Chunk Size & Chunk Overlap**: 
     Determines how the grounding document is split for optimal performance during retrieval. Default settings are used for this experiment.
     ##### b. **Embedding Models**: 
     The choice of embedding models affects how documents are vectorized for retrieval. Default embeddings are selected for the current experiment.
    ![indexing](../images/211/settings-2.png)

     #### 3. **Additional Information**
     - Runtime Environment: **Large** with **8 CPUs** and **32 GB RAM**. This can be adjusted based on new environment availability.

        
   - Click **Save** on the bottom.

## Section Summary:
- **AutoAI RAG** helps identify the best pattern for your use case by testing various combinations of models and parameters.
- It measures patterns against specified metrics, generates test results, and ranks them.
- You can customize models, chunk size, embedding methods, and the number of patterns to test.
- For significant updates in your use case, consider re-running the **AutoAI RAG experiment** with new model questions/answers instead of modifying existing parameters.
