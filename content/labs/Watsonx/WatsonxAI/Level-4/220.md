# Generative AI Models Pricing and Sizing

This guide is designed to help IBM Technical Sales professionals understand and estimate the cost and infrastructure requirements for deploying and using **IBM watsonx.ai**, both on **SaaS** and **on-premises**. It includes detailed walkthroughs of the **pricing models**, the **context window implications**, and the use of tools like the **SaaS Pricing Calculator** and the **IBM Sales Configurator**.

---

## 1️⃣ Foundation Model Pricing

One of the most important tasks for a client is estimating the cost of inferencing with foundation models on watsonx.ai.

### 🔢 1.1 What is a Resource Unit (RU)?
- A **Resource Unit (RU)** is defined as **1000 tokens** used across both input and output in a model interaction.
- Tokens are not equal to words. A rough approximation: **1 token ≈ 0.75 words or 4 characters**.
- Pricing is based on the total RUs used during inferencing.

![RU Definition](../images/220/img_01.png)

--

### 📊 1.2 Understanding Model Classes and Costs
- Models are categorized into **input/output classes**. Each class has a **specific cost per RU**.
- Some models like `mistral large` do not follow the standard class system and have fixed pricing.

**Examples:**
- `llama-3-405b-instruct`: 
  - Input: Class 3 ($0.005/RU)
  - Output: Class 7 ($0.016/RU)

- `mistral large`: Fixed rate of **$0.01/RU** for both input and output.

![Model Classes](../images/220/img_02.png)

---

### 🛠️ 1.3 Custom Foundation Model Pricing
- Clients can deploy custom models in **Small**, **Medium**, or **Large** configurations.
- **Charges are hourly**, starting from deployment time until deletion.

---

## 2️⃣ Context Window Considerations

### 🧠 What is a Context Window?
A **context window** determines how many tokens (input + output) the model can consider at once. It's like the model's memory span.

- Example: `mistral large` supports 128K tokens, but **watsonx.ai limits it to 32,768** tokens.
- In chat use cases, **earlier messages can be forgotten** if the total exceeds the context limit.

![Context Window Example](../images/220/img_03.png)

**Recommendation:** Choose models with larger context windows for tasks like long document summarization or multi-turn chat history retention.

## 3️⃣ SaaS Pricing Calculator

The **watsonx.ai SaaS Pricing Calculator** is used to estimate monthly and annual costs for:
- Inference (based on tokens)
- Prompt tuning (per hour)
- Hosting tuned models
- Document extraction (per page)

### 📌 Key Definitions:
- **1 RU = 1000 tokens**
- **Prompt tuning hours ≠ Prompt Lab experiments** (only tuning in Studio is charged)
- **Hosting** is calculated per hour based on deployment size.

![SaaS Pricing Setup](../images/220/img_04.png)

---

### 📈 SaaS Pricing Example (in CAD)

Client Scenario:
- Inference Model: `granite-13b-instruct-v2`
  - Input Tokens: 35B → 35M RU
  - Output Tokens: 4M → 4K RU
- Tuning Model: `flan-t5-xl-3b` → 20 hours/month
- Pages for extraction: 5,000

## 4️⃣ IBM Sales Configurator

Used to size **on-premises** or **SaaS deployments** based on workloads and user expectations.

### 🏢 On-prem Deployment Walkthrough

Use **T-shirt sizes** (Small, Medium, Large) to simplify sizing decisions.

**Small Use Case Example:**
- 8 GPUs (A100/H100, 80 GB)
- 5 active model deployments
- 250 concurrent users in Prompt Lab
- Supports 3 Medium + 1 Small model OR 1 Large + 3 Small models


🧮 The Sales Configurator calculates:
- **vCPUs**
- **Memory**
- **VPC requirements**

---

### ☁️ SaaS Deployment Walkthrough

Sales Configurator can also estimate **watsonx.ai SaaS deployments**, including storage and service credits.

Steps:
1. Select `watsonx.ai` and add required services.
2. Default **Cloud Object Storage (COS)** is added.
3. Choose size (Small/Medium/Large).
4. Credits/month are auto-calculated.

**Example:**
- Medium watsonx.ai deployment + COS (Hot Tier)
- Total: **~8,044 credits/month**
