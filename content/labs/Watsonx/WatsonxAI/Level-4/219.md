## watsonx.ai L4 Practitioner Reference Guide

This comprehensive guide covers key concepts and implementation details for the IBM watsonx.ai Practitioner L4, providing foundational knowledge and practical insights.

### 1. Foundation Models & Platform Architecture

#### Model Types and Access

* **Available Models:** IBM granite, Meta llama, Mistral models, and open-source options
* **Access Method:** Prompt Lab provides no-code environment for experimentation
* **Customization Options:**
    * **Prompt tuning:** Creates lightweight embeddings for behavior customization
    * **Fine-tuning:** Modifies internal model weights (requires more data)

#### Architecture & Deployment Options

* **Deployment Models:**
    * **Software as a Service (SaaS) in IBM Cloud:** Fully managed by IBM
    * **On-premises:** Full control over data and operations
    * **Hyperscaler options (AWS, Azure):** Flexibility with existing cloud infrastructure
    * **Lightweight Engine:** Smaller footprint with consistent APIs

#### Pricing Models

* **SaaS Options:**
    * **Pay-as-you-go (PayGo):** Usage-based without monthly commitment
    * **Standard Plan:** More features with subscription
    * **Essential Plan:** Basic capabilities

### 2. Retrieval Augmented Generation (RAG) Architecture

#### RAG Flow Patterns

* **Standard Flow:**
    ```
    Question → Search (retrieve relevant context)
    Instructions + Search results + Question → LLM
    LLM generates final completion using retrieved context
    ```

#### RAG Components

* **Embedding Models:**
    * **Purpose:** Convert text into vector representations for semantic search
    * **Function:** Transform both organizational content and queries into vector space
    * **Optimization Metrics:**
        * **Answer Faithfulness:** Measures how closely outputs match source material
        * **Answer Correctness:** Measures accuracy of responses
        * **Context Correctness:** Measures relevance of retrieved context

#### Pattern Configuration

* Embedding Model, Chunk size and overlap settings affect retrieval quality
* Results ranked by chosen optimization metrics (highest-scoring at top)
* Different patterns can be tested and compared

### 3. Technical Implementation

#### Cloud Object Storage (COS) Integration

* **Creating Access Credentials:**
    1.  Navigate to COS instance → "Service Credentials"
    2.  Create "New credential" with HMAC authentication enabled
    3.  Select "Manager" role for appropriate access
    4.  Access key and Secret key are provided in credentials
* **Finding Endpoints:**
    * Located in COS bucket under "Configuration" tab
    * Region-specific endpoints must be used for connections

#### Deployment Requirements

* **Custom Foundation Models:**
    * Must have supported architectures (not all models are compatible)
    * Require sufficient computing resources (GPUs/VPCs)
    * Standard plan typically needed for GPU access
    * Billed by the hour based on the size of the configuration.
* **Hugging Face Integration:**
    * Requires Hugging Face access token
    * Download via `huggingface-cli`
    * Architecture compatibility must be verified

#### Resource Management

* **Token Usage:**
    * 1 Resource Unit (RU) = 1,000 tokens
    * For most models, the cost is the same. Some models, however, have different cost for 1 RU of input tokens versus 1RU of output tokens.
    * Token limits vary by plan and deployment model
* **Computing Capacity:**
    * "Not enough computing capacity" errors indicate resource limitations
    * On-premises deployments need sufficient vCPU/GPU
    * Cloud deployments have Capacity Unit Hour (CUH) allocations

### 4. Enterprise Integration & Governance

#### Project & Asset Management

* **Working with Notebooks:**
    * Add via "New Asset" → "Work with data and models in Python or R notebooks"
    * AutoAI RAG experiments can run through Jupyter Notebooks
* **API Integration:**
    * Enterprise-grade APIs provide consistent behavior across deployments
    * Same APIs available in Lightweight Engine as in full service
    * User API key required for task credentials in AutoAI RAG.

#### Governance & Monitoring

* **watsonx.governance:**
    * Can govern models across platforms (including AWS models)
    * Provides factsheets, fairness metrics, and explainability tools
    * Essential for regulatory compliance
* **Quality Monitoring:**
    * Metrics for model drift and performance
    * Versioning and lineage tracking
    * Optimized for enterprise requirements

### 5. Advanced Features & Integration

#### AI Agents & Orchestration

* **AI Agents:**
    * Can make autonomous decisions within defined parameters
    * Require clear goals, backstories, personas, and tasks
    * Operate within constraints set by human designers
* **Orchestration Layer:**
    * Provides unified end-user experience
    * Coordinates between different AI components
    * Enables consistent interfaces for knowledge workers

#### Developer Tools

* **Language Support:**
    * Python and Node.js primarily supported
    * Notebooks provide flexible development environment
* **Code Assistance:**
    * watsonx Code Assistant helps with development
    * Integrates with common development workflows

### 6. Installation & Configuration

#### Red Hat OpenShift Setup

* **Installation Options:**
    * Red Hat Console recommended for OpenShift AI operator installation
    * Environmental variable file simplifies installation process
    * Full control requires on-premises deployment
* **Resource Planning:**
    * GPU and VPC requirements must be considered
    * Hardware specifications depend on models and workloads

#### Troubleshooting Common Issues

* **Missing Task Credentials:** Create account API key
* **Deployment Failures:** Check resource availability and plan type
* **Connection Errors:** Verify endpoint and credentials

*Note: This guide reflects platform capabilities as of its creation date. Some specifics may evolve as the platform is updated.*
