# Reference Guide: Core Insights into watsonx.ai AI Technologies

This guide offers a comprehensive overview of advanced AI capabilities within the watsonx.ai platform, focusing on Auto AI RAG, Custom Foundation model, and strategic resource management. It draws from practical observations to provide a conceptual foundation, highlighting essential aspects of these technologies for a well-rounded understanding without delving into step-by-step instructions.

## AutoAI RAG

The watsonx.ai platform enhances large language model (LLM) performance through retrieval-augmented generation (RAG), a process that integrates external document context to improve response quality. The workflow typically begins with a query triggering a search, followed by refined instructions, retrieval of relevant data, processing by an LLM, and culminating in a final response. This approach is particularly effective for users new to RAG, providing a seamless way to leverage external knowledge. When working with complex documents such as PDFs, Excel, or Word files, binary formats can pose challenges, but leveraging advanced extraction tools ensures the data is readily usable for RAG applications.

Experimentation is central to optimizing RAG workflows, often involving various configurations to enhance performance. These experiments are evaluated using specific metrics that assess different aspects of the generated responses. One metric, known as Answer Faithfulness, focuses on token precision, measuring how much of the generated answer aligns with the retrieved context to ensure it remains grounded in the source material. Another metric, called Answer Correctness, compares the output against an expected model answer, checking for key token inclusion to gauge accuracy. A third metric, termed Context Correctness, evaluates the relevance of the retrieved context by considering the ranking of answers provided by the LLM, ensuring the most pertinent information is prioritized. Typically, one of these metrics is selected per experiment to guide optimization efforts. The platform displays results as each pattern run completes, arranging them with the highest-scoring pattern at the top based on the chosen metric, and the lowest at the bottom.

Retrieval strategies can be tailored to document complexity, with options to include surrounding context (window method) or focus on key snippets (simple method). Core components of a RAG pattern include the embedding model, chunk size, and chunk overlap, which together ensure efficient data handling. For instance, dividing content into manageable portions—commonly referred to as chunking—enhances retrieval and processing efficiency by the LLM, particularly when stored in vector databases. Lightweight embedding models, such as all-MiniLM-L6-v2, are often used, typically downloaded from open repositories like Hugging Face, requiring an access token for retrieval.

Practical implementation often occurs in notebook environments, necessitating components like API access, project identifiers, cloud storage buckets for hosting documents, secure authentication keys, and vector store connections (e.g., Milvus) for indexing. Solutions such as cloud storage or discovery tools can be imported to support these workflows. If warnings about missing credentials arise, generating a new API key can resolve the issue, ensuring uninterrupted operation. Additionally, users can tune LLM behavior by adjusting settings—for example, opting for a sampling approach in decoding introduces diverse word choices, contrasting with more deterministic methods, allowing for greater variability in responses.

## Custom Foundation Models (CFM)

The platform supports the integration of externally developed AI models, enabling tailored solutions for specific needs. A key requirement for deployment is ensuring the model adheres to a supported architecture, as outlined in IBM documentation, and is in a secure format like safetensors. Not all models from external sources, such as Hugging Face, are deployable, so compatibility must be verified before proceeding. Models are uploaded to cloud storage systems, where files are stored and accessed via secure connections established through new service credentials that include authentication keys. The endpoint for these connections can be found by navigating to the configuration tab within the storage bucket, ensuring seamless access to model files.

Deployment is constrained by resource limits, allowing up to four small, two medium, or one large configuration to be active simultaneously. Insufficient computing capacity, such as the lack of GPUs, can prevent successful deployment, often resulting in errors that highlight the need for additional resources. Costs are accrued hourly based on the configuration size, distinct from storage fees associated with hosting model files, making resource management a critical consideration. If deployment fails due to expired credentials, generating a new user API key can resolve the issue. Once deployed, these models are well-suited for real-time inferencing, ideal for applications requiring immediate responses, though deactivation post-use is recommended to manage expenses.

## Sizing and Sales Configurator

Effective resource planning is essential for deploying AI solutions on watsonx.ai, with deployment options tailored to organizational needs. Entities requiring full control over data and access to high-performance resources, such as GPUs and virtual cores, often opt for on-premises setups to ensure compliance and performance, particularly in sensitive sectors like finance. Startups or organizations exploring the platform without long-term commitments might prefer a pay-as-you-go model, enabling cost-effective evaluation of custom model inferencing without monthly subscriptions. A configurator tool supports both on-premises and cloud-based deployments, assisting in determining client requirements.

Cost structures vary across models, with some having different rates for input versus output tokens—typically lower for inputs, with a multiplier (e.g., 2x) applied to outputs, reflecting the higher computational demand of generation. Roles such as manager or administrator are crucial for overseeing these deployments, ensuring proper configuration and resource allocation.
