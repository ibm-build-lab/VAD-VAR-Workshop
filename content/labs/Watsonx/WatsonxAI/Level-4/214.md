# Custom Foundation Model

## Introduction
IBM’s generative AI strategy is open, trusted, and performant. IBM watsonx.ai is designed to work with models from different sources: IBM-developed models, open source, and other third-party models. 

IBM watsonx.ai provides a set of carefully curated models, which include IBM’s Granite series models, Meta’s llama models, Goggle’s flan models, and Mistral AI’s mistral and mixtral models. These models provide a wide range of generative AI use cases. For example:

- Generation
- Extraction
- Classification
- Summarization
- Question Answering
- Code generation and conversion

IBM has recognized that clients may have been working with models that they have found satisfactory or might have tuned a model to support their business use cases. Clients want to deploy these models within watsonx.ai to use the rich features. For example:

- Model governance, AI automation, and deployment
- Integration with watsonx.data and watsonx.governance
- Integration with various AI Assistants
  
The watsonx.ai Custom Foundation Model feature allows clients to bring their own model and deploy it on watsonx.ai. This feature provides the flexibility for clients to implement the AI solutions that are right for their use case. Always consult Supported model architectures on [Planning to deploy a custom foundation model](https://eu-de.dataplatform.cloud.ibm.com/docs/content/wsj/analyze-data/deploy-custom-fm-plan-cloud.html?context=wx&audience=wdp) to ensure the model that you want to add is based on a supported architecture. 


## Prerequisites & Getting Started (Short Version):

- Create a Hugging Face account: https://huggingface.co/join

## Lab
To add a custom foundation model to **watsonx.ai**, follow these key steps:

- Check if the model is supported by watsonx.ai  
- Get the model files (e.g., from Hugging Face)  
- Convert the model if needed  
- Create a project in watsonx.ai (via TechZone reservation)  
- Upload the model to Cloud Object Storage (COS)  
- Set up a deployment space and link it to your COS  
- Create a model asset from COS content  
- Deploy the model  
- Use it in watsonx.ai

## Downloading a Model from Hugging Face

---

1. **Open a terminal** on your Mac OS or Linux workstation.  
2. **Create a directory** and a new Python virtual environment (update `<username>` accordingly):

    ```bash
    cd /Users/<username>/Downloads
    mkdir CFM
    python -m venv /Users/<username>/Downloads/CFM/venv
    ls /Users/<username>/Downloads/CFM
    ```

    You should see a `venv` directory under `CFM`.
    ![venv](../images/214/image_page15_1.png)

3. **Activate the virtual environment**:

    ```bash
    cd /Users/<username>/Downloads/CFM
    source venv/bin/activate
    ```

    > **Note:** You’ll notice your terminal prompt reflects that you’re now inside the `venv`.
    ![activate](../images/214/image_page15_2.png)

4. **Create a subdirectory** to hold the model:

    ```bash
    mkdir flan-t5-base
    ls -l
    ```
    ![ls](../images/214/image_page16_1.png)

5. **Install the Hugging Face CLI tool**:

    ```bash
    pip install -U "huggingface_hub[cli]"
    ```
    ![install](../images/214/image_page16_2.png)
    > **Note:** Ensure your Python version is 3.9 or higher for smooth compatibility.

6. **Verify the CLI installation**:

    ```bash
    huggingface-cli --help
    ```
    ![cli](../images/214/image_page17_1.png)
    > **Note:** If the `--help` output doesn't include the download option, your Python version may be outdated.

7. **Set up required environment variables** (remember to use your actual token and path):

    ```bash
    export HF_TOKEN="<your Hugging Face token>"
    export MODEL_NAME="google/flan-t5-base"
    export MODEL_DIR="<your base directory>/CFM/flan-t5-base"
    ```

    > **Note:** **Your Hugging Face access token is essential here.** You should’ve saved it earlier—if not, generate a new one. You also need to use the full path name you saw earlier. 
    **google/flan-t5-base**. 
    ![cred](../images/214/image_page17_2.png)

8. **Log in and download the model**:

    ```bash
    huggingface-cli login --token ${HF_TOKEN}
    huggingface-cli download ${MODEL_NAME} --local-dir ${MODEL_DIR} --cache-dir ${MODEL_DIR}
    ```

    > **Note:** Expect around **12 files**, totaling approximately **4 GB**. Some models can be significantly larger.
    ![model-files](../images/214/image_page18_1.png)

9. **Verify the download**:

    ```bash
    ls /Users/<username>/Downloads/CFM/flan-t5-base
    ```

    > You should see all the model files required for deployment.
    ![verify](../images/214/image_page18_2.png)



### Converting the Model to the Required Format (if necessary)

To deploy a **custom foundation model** on `watsonx.ai`, the model **must be in `safetensors` format**.

- For example, the `flan-t5-base` model includes a `model.safetensors` file, which is ready for deployment.
- If your downloaded model does **not** include a `.safetensors` file, you'll need to **convert it**.

> 📌 **Why safetensors?**  
> The `safetensors` format is a secure and efficient alternative to PyTorch's `.bin` format. It ensures faster loading and prevents arbitrary code execution during deserialization — a key requirement for production environments like `watsonx.ai`.

#### 🔧 How to Convert:
Instructions for conversion are provided in the guide:  
[Downloading a custom foundation model and setting up Storage](https://dataplatform.cloud.ibm.com/docs/content/wsj/analyze-data/deploy-custom-fm-storage-cloud.html?context=wx&audience=wdp)
➡️ Refer to the section: **_Converting a model to the required format_**

## Considerations for Custom Foundation Models

Custom Foundation Models (CFMs) offer flexibility to bring in models you're familiar with — or have already fine-tuned — into the watsonx.ai platform. This lab guided you through the steps to import and deploy one.

Here are key considerations to keep in mind:

1. **Not all models are supported**  
   Always check the [supported architecture list](https://eu-de.dataplatform.cloud.ibm.com/docs/content/wsj/analyze-data/deploy-custom-fm-plan-cloud.html?context=wx&audience=wdp#architecture) before attempting an import.

2. **Model card data is not automatically imported**  
   Hugging Face models often include a model card, but this is **not imported** into watsonx.ai. Use the **Description** field during deployment to enter important details manually.

3. **Deployment limits**  
   You're limited to:
   - 4 **small** model deployments  
   - 2 **medium** model deployments  
   - 1 **large** model deployment  
   You can remove existing deployments to free up capacity if needed.

4. **There is a cost**  
   Deployment incurs billing based on model size. See the [Hourly billing rates](https://dataplatform.cloud.ibm.com/docs/content/wsj/getting-started/wml-plans.html?utm_source=skills_network&utm_content=in_lab_content_link&utm_id=Lab-432&context=wx&audience=wdp).

5. **Limitations**  
   - The limitations are as shown [here](https://www.ibm.com/docs/en/watsonx/saas?topic=model-planning-deploy-custom-foundation).
